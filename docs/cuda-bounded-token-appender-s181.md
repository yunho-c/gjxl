# S181: bounded, specialized AC token appending

The candidate passes its precommitted screen gate: all six coefficient-token
worker deltas and all six AC-tokenize wall deltas improve. Worker reductions
are 6.45–14.64%. Whole time remains mixed, including two slower 4K results
with large shifts in earlier quantization. Advance the unchanged candidate
to broader qualification; do not promote it or claim an end-to-end speedup
from this screen. Production remains unchanged and the goal remains active.

## Question and scope

S180 removed compiled sparse rank helper calls but missed its performance
gate. This stage targets the larger per-token append/population operation,
without changing sparse ranking, coefficient decisions, reservation policy,
or GPU work. The parent is `069a2f1f1cf0a4172c936c2a957c6b609c9df5cf` on
`feat/cuda`; production remains the qualified S168 implementation.

Evidence is under `build-cuda-ninja/profiles/s181-artifacts`, with versioned
`s181_*` helpers beside it. All 343 production source files remain unchanged.
The candidate is an isolated serializer experiment, not a public API change,
compatibility layer, minimum-ISA change, or relaxed input-validation policy.

The original direct tokenizer calls `AppendDirectAcToken` once for each
nonzero-count token and each emitted coefficient token. S43 already replaced
string-owning success results with a private error enum. The remaining
helper checks context, symbol, slot, and counter bounds, branches on whether
to collect populations, and returns an error enum for each token.

## Why the removed checks are unreachable here

This optimization applies only to the encoder-only primitive's documented
validated-frame/order/map contract. `encoder.cpp` validates the frame before
dispatch. The order builder validates its custom permutations and their LLF
prefix; the block-context builder validates its completed map. Prepared
natural orders are generated by the unchanged supported-strategy routine.
The per-group anchor, span, strategy, quant-field, order-size, and final
consumption checks remain. Arbitrary malformed private-helper inputs are
not newly accepted or given an unchecked public entry point.

| Invariant | Bound and reason |
|---|---|
| Group token count | A group covers at most 32 x 32 blocks / 65,536 coefficients per channel. The original reservation bound is at most `3 * (65536 + 1024) = 199680` tokens. |
| Transform shape | Each supported transform has `N = 64B` coefficients and an LLF prefix of `B` entries, where `B` is 1, 2, 4, 8, or 16. |
| Density-table indexes | Before emission, `1 <= remaining <= N - scan`. Thus `ceil(remaining/B) + floor(scan/B) <= 64`, with both normalized indexes in 1..63. |
| Local coefficient context | Exhausting all 4,032 normalized index/previous-bit combinations satisfying that triangle gives contexts 0..457, not an unconstrained Cartesian table maximum. |
| Final context | For `C` block contexts, both context formulas stay below `495C`. Valid maps have at most 16 block contexts, so there are at most 7,920 final contexts. |
| Fixed HybridUint symbol | For uint32 values below 16, symbol equals value. Otherwise exponent is 4..31 and the two retained mantissa bits are 0..3, so symbol is at most 127 and extra-bit count at most 29. |
| Population slot | Slots begin missing and populations begin empty for each collecting group. Each context creates at most one slot, so the slot count is below the uint16 missing sentinel. |
| Population counters | Zero-initialized counts receive at most 199,680 increments. Token count is no larger, and extra-bit total is at most `199680 * 29 = 5790720`. |

The candidate additionally checks the conservative token budget once after
the unchanged overflow-safe reservation calculation. Compile-time assertions
pin the supported geometry, token/alphabet bounds, and reachable density
contexts. The existing collecting-path context-count guard, slot reset, and
population clearing/reservation remain. These arguments depend on reset
population state and a valid LLF-preserving permutation; they are not claims
about arbitrary preloaded counters or invalid order tables.

## Candidate and controls

A private clone specializes population collection once per group. Its
force-inline `S181Append<Collect>` writes the same value/context vectors and,
when collecting, performs the same fixed-HybridUint mapping, first-use slot
creation, histogram updates, extra-bit accounting, and maximum-symbol update.
It removes only the unreachable per-token error checks and enum handling.
Standard vector capacity/allocation behavior is retained. No raw vector
storage manipulation, dense expansion, payload copy, or S180 rank intrinsic
is introduced.

Original modes 0/1 call the same original template. Candidate modes 2/3 call
the same bounded path for both dense and sparse groups. A common diagnostic
selector is changed only between joined encodes. Common per-group rows
record dispatch, anchors, token counts, and capacities inside Encode; setup,
reference encoding, prior-result clearing, validation, and read-only NVML
endpoints are outside. Concurrent diagnostic reconfiguration is unsupported.

Both paths publish the local candidate output only after success. The
original `bad_alloc`/`length_error` handlers remain; scratch state is not
transactional, as before. Allocation failure handling is supported by the
unchanged catch/publication structure, not by allocation-fault injection in
this stage.

Source auditing reconstructs the complete original translation unit and
checks the exact clone/dispatch transformation. Native auditing covers every
normal dense/sparse int8/int16/int32 original and both candidate collection
specializations. The original six templates each retain two checked append
call sites; the twelve candidate templates contain neither checked nor
bounded append calls. Original instruction bytes and relocation
offsets/types/targets match the frozen production library after normalizing
only anonymous-namespace identifiers. This unlinked-object comparison does
not establish whole-DLL identity or neutrality of the surrounding scaffolding.
Full ASAN disassembly is retained without a normal-machine-code identity
claim. Both whole DLLs contain eleven unchanged CUDA modules.

Inlining grows the collecting function body, a tradeoff measured by the
screen rather than assumed harmless. These are unlinked instruction bytes,
not total active code size including callees or whole-DLL size:

## Qualification and fixed-screen protocol

The private fixture compares original dense/original sparse/candidate dense/
candidate sparse tokens and every population field, with unchanged vector
capacities. It covers 128 frames / 320 groups, all seven strategies and mixed
layouts, int8/int16/int32, eight patterns including extrema, natural/custom
orders, population collection on/off, unaligned spans, reversed sparse
payload-word order, nonzero LLF/suffix entries, and reused scratch. Its five
validated maps include quantization splits and the maximum 16 contexts /
15 thresholds. Null scratch/output and short spans must leave output intact.

Additional bounds fixtures exercise all 4,032 reachable normalized contexts,
548,352 mapped-context combinations, and 677,691 actual scan/remaining
normalizations across the supported block counts. Independent HybridUint
encoding checks 240 interval endpoints covering all 128 symbols. Checked
and bounded appenders are compared through all 7,920 legal slots and through
199,680 maximum-value appends, with collection both enabled and disabled.
An unchanged public-template/scalar/population reference fixture runs against
the candidate dispatch separately, including scratch reuse across groups.

Whole preflight covers eleven inputs, automatic/eight requested CPU threads,
normal/ASAN builds, then CUDA memcheck on 4K and initcheck on Keong. Each whole
call checks bytes and the complete summary against frozen S168, with image
codestream oracles, native storage, width, dispatch, token/anchor counts, and
original capacities checked against frozen S169/S172 records. The corpus
contains derived photograph sizes and synthetic controls, not independent
native-resolution images or other machines.

The fixed screen uses 1080p, 4K, and Keong at eight threads; two reversed
process-order passes; eight warm-up and sixteen measured rounds. The four
Williams orders (`0132`, `1203`, `2310`, `3021`) balance positions and directed
within-round predecessors. Primary deltas are medians of within-round
candidate-duplicate means minus original-duplicate means; individual pairs
and same-path disagreements are retained. Worker work is nested, not
additive wall time.

The screen cannot authorize promotion. Its precommitted broader-test gate
requires six of six lower coefficient-token worker deltas and at least four
lower AC-tokenize wall deltas. All samples remain; no filtering or rescue
rerun is allowed. No build, sanitizer, profiler, compression, or heavy hashing
runs during timing. Ordinary shared-machine activity and light report
editing remain limitations. No power, clock, cooling, affinity, priority,
driver, firewall, or security setting is changed.

runs after quantization in each Encode. Those earlier changes are therefore
not direct current-call work introduced by this appender. Cross-encode
cadence/carryover is a hypothesis to test, not a demonstrated cause; ordinary
shared-machine variation and other operating-state effects remain unresolved.

## Decision and next experiment

Preserve this candidate unchanged for a broader all-eleven-input,
automatic/eight-thread campaign with repeated process-order controls. Add
separately specified contiguous-policy steady-state comparisons on 4K and
Keong, with same-path duplicates, to check whether the local gain survives
continuous full-encoder use and to probe the interleaved screen's earlier
quantization shifts. Define that follow-up protocol before running it; do
not retrospectively retune this screen or infer promotion from worker time.
Any eventual production integration needs its own verification.

The existing GPU perceptual work, tile scheduling, and resident handoff
questions remain within the full optimization objective. This checkpoint
completes a bounded correctness/screen experiment, not that objective.
